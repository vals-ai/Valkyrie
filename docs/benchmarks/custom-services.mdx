title: Custom benchmark services
description: Connect Valkyrie to a benchmark service endpoint.

A benchmark service supplies tasks and evaluates run outputs. A URL you save overrides the hosted service with the same name for your runs.

Full syntax is in the [`benchmark service set`](/reference/cli/benchmark#service-set), [`benchmark service list`](/reference/cli/benchmark#service-list), and [`benchmark service remove`](/reference/cli/benchmark#service-remove) reference.

## Save an endpoint

```bash
valkyrie benchmark service set swebench https://my-tunnel.ngrok.io
```

The Tracker saves the URL for you in the current organization, so `valkyrie run start` and `valkyrie benchmark tasks` use it on every machine unless they pass `--ignore-custom-services`. Save it while signed in with `valkyrie login`; access keys can't change it.

The Tracker must be able to reach the endpoint, so a service running on your machine needs a [reverse tunnel](#expose-a-local-service).

## List services

```bash
valkyrie benchmark service list
```

It checks each service's health and supports `[h]` for previous, `[l]` for next, and `[q]` to quit.

## Remove a saved endpoint

```bash
valkyrie benchmark service remove swebench
```

Your runs of that benchmark go back to the hosted service.

## Build a service

Use the public [create-benchmark-service](https://github.com/vals-ai/create-benchmark-service) utilities to implement a compatible service, or follow [convert a benchmark into a service](/benchmarks/convert-a-benchmark).

## Expose a local service

A service running locally can be tested against hosted Valkyrie through a reverse tunnel. ngrok is the shortest path, but any tunnel that gives you a public HTTPS URL works.

1. [Sign up for ngrok](https://dashboard.ngrok.com/login) and follow its [setup and installation steps](https://dashboard.ngrok.com/get-started/setup).
2. Start the service, either `make dev` or `make docker-build && make docker-run` (the container publishes port `8001`).
3. Forward the port the service is listening on:

```bash
ngrok http 8001
```

4. Save the forwarding address ngrok prints:

```bash
valkyrie benchmark service set <benchmark-name> https://hemagglutinative-vonnie-fungic.ngrok-free.dev
```

The forwarding address changes each time a free-tier tunnel restarts, so save the new address after every restart.

## Deploy the service

A tunnel is fine while iterating, but a service other people run against needs a stable HTTPS endpoint. The generated project ships a `Dockerfile` that serves `main:app` with uvicorn on container port `8001`, so any host that can run a container and route WebSocket traffic to it works.

### Build and publish the image

<Steps>
  <Step title="Build the image">
    ```bash
    make docker-build
    ```

    This tags the image `benchmark-service:latest`. The build takes a `SERVICE_VERSION` argument that becomes the version reported by `GET /version`; CI passes the git tag.
  </Step>
  <Step title="Tag it for your registry">
    ```bash
    docker tag benchmark-service:latest <registry>/<benchmark-name>-benchmark-service:<tag>
    ```
  </Step>
  <Step title="Push it">
    ```bash
    docker push <registry>/<benchmark-name>-benchmark-service:<tag>
    ```
  </Step>
</Steps>

Deployment guides for common container hosts: [AWS App Runner](https://docs.aws.amazon.com/apprunner/latest/dg/service-source-image.html), [ECS with an Application Load Balancer](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/service-load-balancing.html), [Google Cloud Run](https://cloud.google.com/run/docs/deploying), and [Fly.io](https://fly.io/docs/launch/deploy/).

### Configure authentication

| Variable | Purpose |
| --- | --- |
| `AUTH_DISABLED` | `true` serves every request without a credential. Local development only; `/v1/*` still refuses to serve. |
| `DESCOPE_PROJECT_ID` | Descope project that issues and validates caller access keys. Required when auth is enabled. |
| `DESCOPE_TENANT_ALLOWLIST_JSON` | Tenant allowlist, as inline JSON. This is how a self-hosted service declares who may call it. |
| `DESCOPE_ALLOWLIST_PATH` | Path to the same structure as YAML, for local runs. |
| `DESCOPE_AUTH_CACHE_TTL_SECONDS` | Positive-auth cache lifetime. Defaults to 3600. |

Authenticated callers send their Descope access key in the `X-Descope-Api-Key` header. The key must resolve to exactly one tenant, and that tenant must appear in `DESCOPE_TENANT_ALLOWLIST_JSON`, so the allowlist is what actually grants access:

```json
{
  "tenants": {
    "T2abc...": {
      "datasets": ["default", "hard"],
      "evaluation_quota": { "limit": 500, "period": "week" },
      "trial_mode": false
    }
  }
}
```

`datasets` is an explicit list of the dataset variants the tenant may request. `default` has to be listed too, and an empty list grants nothing. `evaluation_quota` caps evaluation requests per period, and `trial_mode` sanitizes `/v1/evaluate` and `/v1/score` responses down to score-only fields. Unknown keys are rejected.

<Warning>
  With auth enabled and no allowlist source configured, the service starts and logs a warning but rejects every authenticated request. `AUTH_REQUIRED` is no longer supported: static bearer auth was removed, and setting it to a false value fails startup.
</Warning>

### Save the endpoint

Store a Descope access key that the allowlist grants as a secret, then save the endpoint with it:

```bash
valkyrie secret set benchmark-key
valkyrie benchmark service set <benchmark-name> https://benchmark.example.com \
  --auth-secret benchmark-key --auth-header X-Descope-Api-Key
```

See [Benchmark authentication](/benchmarks/authentication).
