---
title: "Connect a benchmark service"
description: "Point your runs at your own copy of a benchmark service, on your machine or deployed."
---

By default, runs use the benchmark services that Vals AI hosts. When you save your own URL
for a benchmark, your runs of that benchmark use your service instead, on any machine. To
build a service, see [Convert a benchmark into a service](/benchmarks/convert-a-benchmark).

## Save a service URL

```bash
valkyrie benchmark service set swebench https://benchmark.example.com
```

The URL is saved for you in the current organization, and `valkyrie run start` and
`valkyrie benchmark tasks` use it until you remove it. Saving needs a login; access keys
can't change it. The Tracker must be able to reach the URL, so a service on your machine
needs a [reverse tunnel](#expose-a-local-service).

To send a credential with every request, see
[Benchmark authentication](/benchmarks/authentication).

## List services

```bash
valkyrie benchmark service list
```

This lists the hosted services and your saved URLs, and checks that each one responds. Page
through the list with **h** and **l**, and quit with **q**.

## Go back to the hosted service

```bash
valkyrie benchmark service remove swebench
```

To use the hosted service for one run and keep your saved URL, pass
`--ignore-custom-services` to `valkyrie run start` instead.

## Expose a local service

Hosted Valkyrie can reach a service on your machine through a reverse tunnel. These steps
use [ngrok](https://ngrok.com); any tunnel that gives you a public HTTPS URL works.

1. [Sign up for ngrok](https://dashboard.ngrok.com/login) and follow its
   [setup steps](https://dashboard.ngrok.com/get-started/setup).
2. Start the service in a container, which serves on port `8001`:

   ```bash
   make docker-build

   make docker-run
   ```

3. Forward the port:

   ```bash
   ngrok http 8001
   ```

4. Save the forwarding address that ngrok prints:

   ```bash
   valkyrie benchmark service set swebench https://example-tunnel.ngrok-free.dev
   ```

A free ngrok address changes each time the tunnel restarts, so save the new address after
every restart. To point a run that already started at the new address, retry it with
[`--benchmark-url`](/runs/manage#resume-or-retry).

## Deploy the service

A tunnel works while you iterate. A service other people run against needs a stable HTTPS
address. The generated `Dockerfile` serves the app on port `8001`, so any container host that
routes HTTPS and WebSocket traffic to it works.

```bash
# Build benchmark-service:latest
make docker-build

docker tag benchmark-service:latest registry.example.com/swebench-benchmark-service:v1

docker push registry.example.com/swebench-benchmark-service:v1
```

Then deploy the image with your host's guide, for example
[AWS App Runner](https://docs.aws.amazon.com/apprunner/latest/dg/service-source-image.html),
[Amazon ECS behind an Application Load Balancer](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/service-load-balancing.html),
[Google Cloud Run](https://cloud.google.com/run/docs/deploying) or
[Fly.io](https://fly.io/docs/launch/deploy/). Before you share the address,
[require a credential](/benchmarks/authentication#require-a-credential).
