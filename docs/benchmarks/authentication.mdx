---
title: Benchmark authentication
description: Keep a benchmark service's credential in your organization's secrets and send request-specific headers.
---

Benchmark-service credentials are separate from the login or access key you use with the Tracker. The Tracker keeps them as secrets of your organization and adds them to its requests to the service.

## Save a credential with the service

Store the credential as a secret, then name the secret when you save the service URL:

```bash
valkyrie secret set swebench-key
valkyrie benchmark service set swebench https://benchmark.example.com --auth-secret swebench-key
```

The Tracker sends the secret's value as the `Authorization` header on every request to that service, for your runs and task listings. Store the value exactly as the header should carry it, such as `Bearer <token>`. Services built from create-benchmark-service read a Descope access key from `X-Descope-Api-Key` instead; see [Save the endpoint](/benchmarks/custom-services#save-the-endpoint).

The secret has to exist in your organization's secrets when you save the service. Saving the service again replaces its URL and credential, so leave out `--auth-secret` to stop sending one; `valkyrie secret set` changes the credential's value without saving the service again. Headers the Tracker controls, such as `X-Api-Key` and `Host`, are refused. Runs and task listings with `--ignore-custom-services` use the hosted service and don't send the saved credential, and a local Tracker, which has no organization secrets, refuses it. Resuming or retrying a run doesn't send it again; pass the credential with `-H` to `valkyrie run resume`.

See the [`benchmark service set`](/reference/cli/benchmark#service-set) and [`secret set`](/reference/cli/secret#set) reference for full syntax.

## Send runtime headers

Use repeatable `-H` or `--header` pairs:

```bash
valkyrie run start \
  --benchmark my-benchmark \
  --agent sweagent \
  -H X-Custom-Header my-value \
  -H X-Another-Header another-value
```

Runtime headers are sent alongside the saved credential, which always goes with the saved URL.
