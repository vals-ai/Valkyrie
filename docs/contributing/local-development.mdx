## Prerequisites

- Python 3.12
- [uv](https://github.com/astral-sh/uv), for example `brew install uv`
- Docker, for the local tracker stack

## Install the CLI from source

```bash
make install
```

This creates `.venv` and installs the dependencies declared in `pyproject.toml`.

To run `valkyrie` without the `uv run` prefix, install it as a tool:

```bash
make tool-install
```

The tool install is editable, so code changes take effect immediately. Run `uv tool update-shell` if the executable is not on your PATH.

## Point the CLI at a local tracker

```env
TRACKER_SERVICE_URL=http://localhost:8000
```

Set this in `.env` or your shell before running CLI commands against a local tracker. The CLI still reads credentials from `~/.config/valkyrie/valkyrie.yaml`, created by `valkyrie config init`. See [Configure the CLI](/get-started/configuration).

## Run the tracker locally

```bash
make tracker-service
```

The API is available at `http://localhost:8000`. Local Compose runs the tracker, PostgreSQL, and Redis only. It does not execute benchmarks. See [Tracker service](/contributing/tracker-service) for the individual targets and test suites.


## Test local runtime adapters

The local adapters compose filesystem artifacts, per-run JSONL logs, transient secrets,
and the CBS Docker provider. Containerized services mount the data directory at the
same absolute path as the host. Artifacts are scoped to the organization. Closing the
runtime discards its execution secrets while preserving artifacts and logs.

Run the Docker integration check from `services/tracker`:

```bash
CBS_DOCKER_ENABLED=true DOCKER_HOST=unix:///var/run/docker.sock \
  uv run pytest tests/integration/docker
```

Use your Docker context's Unix socket for `DOCKER_HOST` when it differs. The check
creates a disposable container, transfers a frozen agent bundle, executes it, verifies
its output, and deletes the container. Local transfers use provider file upload and
preserve executable files without requiring curl or unzip in the image.

Configure Tracker in `/absolute/path/to/local-server.yaml`:

```yaml
execution_environment: local
local_data_root: /absolute/path/to/valkyrie-data
local_secrets_file: /absolute/path/to/existing.env
```

`local_secrets_file` is optional for agents without secrets. The executor reads only
keys declared by the agent contract, directly from that file, for each start or
resume. Valkyrie stores the file path, not its contents. Keep the file outside the
artifact directory. Tracker and ExecutorHost must use the same filesystem paths and Docker daemon.

Configure the CLI or SDK in `/absolute/path/to/local-client.yaml`:

```yaml
tracker_url: http://127.0.0.1:8000
custom_benchmark_services:
  my-benchmark: http://127.0.0.1:8001
```

`tracker_url` is the only required client setting. Add `api_key` when Tracker requires authentication.

Start PostgreSQL and Redis with `docker compose -f services/tracker/docker-compose.yml up -d postgres redis`.
Set `DATABASE_URL` and `REDIS_URL` for those services, then run the existing migrations
from `services/tracker` with `uv run alembic upgrade head`. Build the executor on the
machine where it will run, then initialize its release as shown above:

```bash
PYTHONPATH=services/tracker/src uv run --project services/tracker python \
  services/executor_artifact/build.py --output-directory /absolute/path/to/build
```

Set `CBS_DOCKER_ENABLED=true` and `DOCKER_HOST` for Tracker, ExecutorHost, and your
local benchmark service. Start Tracker from `services/tracker`:

```bash
uv run python -m tracker.serve --config /absolute/path/to/local-server.yaml
```

In another terminal at the repository root, start ExecutorHost. Set `DB_HOST`,
`DB_PORT`, `DB_NAME`, `DB_USERNAME`, and `DB_PASSWORD` to the same database used by
Tracker. ExecutorHost uses these settings in addition to the executor's `DATABASE_URL`.

```bash
EXECUTOR_RELEASE_ROOT=/absolute/path/to/releases \
EXECUTOR_CACHE_DIR=/absolute/path/to/executor-cache \
PYTHONPATH=services/tracker/src uv run --project services/tracker python -m taskiq worker \
  --workers 1 --no-configure-logging services.executor_host.supervisor:broker services.executor_host.supervisor
```

Start your benchmark service at its configured address. Then publish an agent and run it:

```bash
export VALKYRIE_CONFIG_PATH=/absolute/path/to/local-client.yaml
valkyrie agent push ./my-agent
valkyrie run start --agent my-agent --benchmark my-benchmark --concurrency 1
```

Use the returned run ID with `run fetch`, `run logs`, `run results`, `run outputs`,
`run stop`, `run retry`, and `run resume`. Tracker serves local agent and artifact
downloads over HTTP. Clients do not need access to `local_data_root`. Local execution supports
image-based Docker tasks; AWS callbacks and cloud secret references are unavailable.

### Run it with hosted-mode authentication

```bash
AUTH_REQUIRED=true \
DESCOPE_PROJECT_ID=<your-project-id> \
DESCOPE_MANAGEMENT_KEY=<your-management-key> \
make tracker-service
```

`DESCOPE_MANAGEMENT_KEY` is server-side tracker configuration. It lets the local tracker resolve the access key's bound user email through Descope's management API when you are testing hosted-mode run attribution. The tracker expects the access-key exchange response to expose the bound user id through custom claims:

```json
{
  "keyId": "K2abc",
  "sessionToken": {
    "sub": "K2abc",
    "customClaims": {
      "user_id": "U2abc"
    }
  }
}
```

Then run `valkyrie config init` and choose hosted mode. Without these variables the service runs in self-hosted mode with no auth and a default organization.

## Check your changes

```bash
make style       # ruff format and ruff check --fix
make typecheck   # basedpyright in strict mode
```

## Preview the documentation

The published documentation is generated from `docs/`. Local preview needs Node.js 20.17 or newer and no Mintlify credentials:

```bash
cd docs
npx mint dev
```

Run `npx mint login` only to test account-backed features such as search and the assistant.

`docs/reference/` is generated from the CLI and SDK source. Run `make docs-reference` after changing a public CLI or SDK surface. CI runs `make docs-reference-check` and fails on stale output.

## Versioning and releases

The `prod` branch uses semantic versioning through [github-tag-action](https://github.com/anothrNick/github-tag-action). Include the tag in the pull request title:

| Tag | Effect | Example |
| --- | --- | --- |
| `#patch` | Patch bump | v0.4.0 to v0.4.1 |
| `#minor` | Minor bump | v0.4.1 to v0.5.0 |
| `#major` | Major bump | v0.5.0 to v1.0.0 |

Binaries are released when a commit is tagged: dev requires tagging a commit manually, prod is tagged and released automatically on push. `valkyrie-sdk` is versioned and published separately.
