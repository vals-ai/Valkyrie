---
title: What is Valkyrie?
description: Why Vals built a microservice benchmarking framework, and how its subsystems fit together.
---

Valkyrie is the result of months of running and investigating agentic benchmarks at Vals AI. Evaluation used to happen on researchers' own machines: one large box, one local copy of the benchmark, results on local disk. That worked until it didn't — at our scale we hit every niche failure mode, and existing harnesses could not scale with us, so we moved the whole process to the cloud as a service where many researchers create and run benchmarks in parallel.

## The problems we hit

<AccordionGroup>
  <Accordion title="Maintainer scalability" icon="git-pull-request">
    When every benchmark lives in one repository, adding a benchmark means a pull request the core team has to review, and every user has to pull changes and reconfigure. Version mismatches are silent and hard to diagnose.
  </Accordion>
  <Accordion title="Infrastructure scalability" icon="server">
    A single large instance has to be sized for peak load, sits idle between runs, and still caps parallelism well below a benchmark with hundreds of tasks. Logs, results, and agent outputs live on that instance's disk, where they are easy to lose and hard to find.
  </Accordion>
  <Accordion title="Submission verification" icon="shield-check">
    When generation happens on the submitter's machine, a maintainer can re-score the outputs but cannot verify the conditions they were produced under — per-task time limits, turn budgets, or network restrictions. Results are only comparable if those constraints are actually enforced.
  </Accordion>
  <Accordion title="Agent integration" icon="package">
    Harnesses that require agents to implement a class or function signature demand far more code than the task needs. The only things that really vary per agent are the install command, the run command, where output lands, and which secrets it needs.
  </Accordion>
</AccordionGroup>

## How Valkyrie solves it

Valkyrie separates the benchmark, the agent, and the infrastructure into independently deployed services.

<CardGroup cols={2}>
  <Card title="Benchmarks as services" icon="plug">
    Each benchmark is its own hosted service, owned by its author. New benchmarks are available as soon as they are deployed — no change to the core harness, and no local copy to modify.
  </Card>
  <Card title="Declarative agents" icon="file-code">
    An agent is a contract: install command, run command, output location, secrets, egress rules. The harness owns orchestration.
  </Card>
  <Card title="Horizontal execution" icon="layers">
    Tasks run in isolated sandboxes provisioned on demand, so parallelism is bounded by provider limits rather than the size of one machine.
  </Card>
  <Card title="Your cloud, your record" icon="database">
    Runs, logs, and artifacts persist in your own AWS account, giving a durable audit trail instead of a local directory.
  </Card>
</CardGroup>

Because generation happens inside infrastructure Valkyrie controls, per-task limits and network restrictions are enforced rather than trusted, and every run keeps the evidence of how it was produced.

## Architecture

```mermaid
flowchart LR
  subgraph clients["Clients"]
    CLI["CLI"]
    SDK["Python SDK"]
  end

  subgraph platform["Valkyrie platform (your AWS account)"]
    Tracker["Tracker<br/>run state, dispatch, API"]
    Executor["Executor<br/>task execution workers"]
    Storage["S3 + CloudWatch + PostgreSQL<br/>artifacts, logs, run history"]
  end

  Sandboxes["Sandbox provider<br/>Daytona / Modal"]
  Services["Benchmark services<br/>tasks + evaluation"]

  CLI --> Tracker
  SDK --> Tracker
  Tracker --> Executor
  Tracker --> Storage
  Executor --> Sandboxes
  Executor --> Services
  Executor --> Storage
```

| Subsystem | Responsibility |
| --- | --- |
| CLI and SDK | Start runs, upload agents, monitor progress, retrieve results |
| Tracker | Owns run state, dispatches tasks, exposes the API |
| Executor | Runs a task end to end: provision sandbox, install and run the agent, collect outputs |
| Sandbox provider | Supplies the isolated environment each task executes in |
| Benchmark service | Serves task definitions and evaluates results for one benchmark |
| Storage | Persists artifacts, logs, and run history in your account |

For the deployed AWS topology, see [self-hosting infrastructure](/self-hosting/infrastructure).
