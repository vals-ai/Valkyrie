Each method's parameters, defaults, and return types are in the [`client.benchmarks`](/reference/sdk/benchmarks#fetch), [`client.agents`](/reference/sdk/agents#list), and [`client.services`](/reference/sdk/services#catalog) reference.

## Benchmarks and tasks

Use `client.benchmarks` for detailed, paginated run views:

```python
from valkyrie.sdk import FetchTasksRequest, TaskStatus

details = await client.benchmarks.fetch(run.benchmark_id)
statuses = await client.benchmarks.statuses([run.benchmark_id])
tasks = await client.benchmarks.tasks(
    run.benchmark_id,
    FetchTasksRequest(status=[TaskStatus.ERROR], limit=25),
)
task = await client.benchmarks.task(run.benchmark_id, tasks.tasks[0].task_id)
artifacts = await client.benchmarks.artifacts(run.benchmark_id, task.task_id)
```

Artifact methods return temporary URLs generated by Tracker. The SDK does not expose internal S3 keys or clients. Tracker task-detail routes do not support task IDs containing `/`; the SDK rejects those IDs before sending a request.

## Logs

`client.logs` reads logs through the authenticated tracker. Omit `task_id` by using `fetch_run` to aggregate every stream in the run, or use `fetch_task` for one task's current stream:

```python
from datetime import datetime, timezone

run_logs = await client.logs.fetch_run(
    run_id,
    query="rate limit",
    start_time=datetime(2026, 1, 1, tzinfo=timezone.utc),
    end_time=datetime(2026, 1, 2, tzinfo=timezone.utc),
)
task_logs = await client.logs.fetch_task(run_id, task_id, query="ERROR")
```

`page_run` and `page_task` expose bounded pages and opaque continuation cursors. The `fetch_*` methods follow every cursor automatically. Log methods accept task IDs containing `/`; this does not change the separate task-detail route limitation above. Follow one task as new events arrive:

```python
async for event in client.logs.stream_task(run_id, task_id):
    print(event.timestamp, event.message)
```

Queries match literal message text. Time bounds require timezone-aware values and are inclusive. Aggregate events include `task_id` when the tracker can resolve the versioned stream.

## Agents

List uploaded agents or request a temporary download URL:

```python
agents = await client.agents.list()
download = await client.agents.download_url(agents.agents[0].name)
```

Local agent packaging and S3 upload or download remain CLI workflows.

## Benchmark services

Discover services, check their health, or fetch dataset task IDs:

```python
services = await client.services.list()
task_ids = await client.services.task_ids("swebench", dataset="default")
```

`list` reads the catalog and then health-checks every service in it. Use `catalog` when you only need the registered endpoints without paying for the health checks:

```python
catalog = await client.services.catalog()
names = [service.name for service in catalog.services]
```

Task IDs come from the custom endpoint registered for that benchmark when one exists. Pass `ignore_custom_services=True` to query the hosted service instead, or `service_headers` to add request headers alongside the stored credential.
