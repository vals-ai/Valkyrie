Valkyrie keeps two things apart: the evaluated results, and the files the agent produced along the way.

<CodeGroup>

```bash CLI
valkyrie run results <run-id> --path ./results.json
```

```python Python SDK
results = await client.runs.results(run_id)
```

</CodeGroup>

Full syntax is in the [`run results`](/reference/cli/run#results), [`run outputs`](/reference/cli/run#outputs), and [`run output`](/reference/cli/run#output) reference, and in [`client.runs.results`](/reference/sdk/runs#results) for Python.

## Download results

The results file holds the scores and the per-task evaluation. Without `--path`, the CLI writes it to `./results-<run-id>.json`.

### Credited-generation timeout accounting (local MVP)

The benchmark task opts in with `credited_generation: { allowance_seconds: B, stage_protocol: "valkyrie-stage/1" }`. `allowance_seconds` is a finite positive generation-only budget, independent of the published `agent_timeout` envelope. Set `stage_protocol: null` to treat the whole agent command as one generation interval; omit `credited_generation` for the legacy `agent_timeout` path. Agents do not declare containment in their contract. An opted-in task requires an effective sandbox provider with `linux_pid_namespace` version 1 and confirmed workload termination.

After `setup_task`, Tracker creates `/run/valkyrie-stage/key` and `/run/valkyrie-stage/ack/`, then sets `VALKYRIE_STAGE_DIR` on the one outer agent command. A staged benchmark reports each generation interval on that command's stdout with authenticated `VALKYRIE-STAGE/1` frames. The signing key and acknowledgements must be readable only by the benchmark orchestration process, never passed or mounted into the model-capable container. Tracker filters valid frames out of the task log and writes `ack/<seq>` only after applying the corresponding transition. The benchmark must await BEGIN acknowledgement before launching its model-capable container and END acknowledgement before starting non-generation work; END follows confirmed nested-container absence. An exact repeat of the last accepted frame is a no-op; its ACK exists or is being published; missing, reordered or conflicting authenticated frames fail closed.

One task has one cumulative allowance. For staged tasks generation is charged from successful Gateway BEGIN, just before publishing the BEGIN acknowledgement, until Tracker receives the matching authenticated END. A simple task charges the whole command interval from before workload construction. BEGIN acknowledgement upload time and END delivery time count against the allowance; setup, evaluation, and gaps between intervals are free. The clock stops before the Gateway END round-trip and remains stopped between intervals. Tracker alone decides exhaustion against `B` plus capped accepted SSP overhead. If an active interval times out or the outer command ends before END, Tracker confirms outer and named nested Docker container absence before sealing accounting.

At an apparent deadline, Gateway arbitration has a shared 10 seconds and remains fenced until confirmed workload absence; only then does Tracker resolve SEAL and persist the summary. any required kill must confirm generation absence by the absolute deadline plus 20 seconds, not 20 seconds after arbitration. Stopping the outer workload remains provider-specific; the local MVP uses effective `linux_pid_namespace` version 1 containment.

Optional SSP credit requires a locally configured External Service Gateway URL and cumulative credit
cap, a working native Model Gateway URL and credential, and an attested agent model. Only an attested
model can receive SSP credit; lack of attestation does not disable the base controlled allowance. This
local MVP does not activate the path in production: deployment configuration and production gateway
integration are not supplied here.

For a configured accounting session, Tracker resolves and validates the original Model Gateway URL
and static credential, then sends the privileged `/service-auth` mint through SSP with that bearer
and `X-SSP-Session-ID`. SSP forwards the mint to Model Gateway and binds the returned native
task-scoped token to the session. Only after minting does Tracker set the sandbox's
`MODEL_GATEWAY_URL` to the SSP URL; `MODEL_GATEWAY_API_KEY` remains the native scoped token,
never the accounting session ID. The sandbox sends model requests through SSP with that bearer;
SSP accounts for them and forwards them to Model Gateway. Tracker uses an internal begin/end control
for active generation intervals, authenticated with `X-SSP-Control-Token`; no adapter, model, or
agent configuration field carries those controls. Tracker revokes the scoped token through SSP using
the original static bearer on sandbox context exit.

The scoped token is nonrenewable and lasts seven days from mint. Tracker rejects a selected task
once its previously persisted wall deadline expires: seven days minus a two-hour teardown margin
from the first post-admission mint (or selected-task start without a native Gateway key). The
deadline survives retries and resumed evaluation, includes setup, generation, evaluation and
pauses, and cannot be extended by a new token. Exceeding it records a terminal wall-time error,
distinct from generation TIMEOUT. A larger configured generation allowance cannot extend this
task-level wall bound. Without SSP configuration, no neutral-time credit is applied; selected
tasks still use the native Gateway mint route with a seven-day token lease where available.

SSP reports cumulative accepted neutral external-service overhead for active intervals. Applied
credit is capped by the configured cumulative cap, so the effective generation allowance is the
benchmark's `allowance_seconds` plus capped credit. An acknowledged `RESUME` establishes a new generation deadline,
never a new task wall deadline.

Selected tasks expose seven nullable fields in each per-task `task_breakdown`:
`accounting_session_id` identifies the accounting session, not a bearer credential;
`base_generation_allowance_seconds` is the benchmark's `allowance_seconds`;
`cumulative_time_credit_cap_seconds` is the credit limit;
`external_service_overhead_seconds` is accepted cumulative overhead;
`external_service_credit_applied_seconds` is the capped credit;
`effective_generation_allowance_seconds` is base plus applied credit; and
`external_service_credit_revision` is the gateway revision at sealing. Without SSP accounting,
these fields remain null even when the task uses the base controlled allowance.

Pass a task subset to recompute `final_score` over only those tasks. The stored full result stays as it was:

```bash
valkyrie run results <run-id> --task-ids task_1,task_2
```

<Warning>
  Combining `--s3` with a task subset overwrites the run's S3 result file with that subset view. Run the command again without filters to put the full result back.
</Warning>

## Download outputs

Outputs are the files the agent itself wrote. Fetch all of them, or only the tasks you care about:

```bash
valkyrie run outputs <run-id> --output-dir ./outputs
valkyrie run outputs <run-id> --task-ids astropy__astropy-7606,django__django-10880
```

To pull one file or directory instead of the whole run, name a path inside the run's benchmark prefix:

```bash
valkyrie run output <run-id> <subpath> --output-dir ./output-dir
```

The output directory defaults to `./<run-id>`.


## Download outputs from Python

Use `await client.runs.download_outputs(run_id, "./outputs", task_ids=["task-id"])` to download and unpack run outputs, including nested task tarballs. Omit `task_ids` for the entire run. Choose a new output directory; existing directories are refused. Downloads and extraction enforce [configurable size and entry limits](/reference/sdk/runs#download-outputs) and reject links or unsafe archive paths.

## Download a specific artifact path

Use `valkyrie run artifacts <run_id> --format json` to list one page of available paths. Continue with the returned `next_cursor` using `--cursor`.

`valkyrie run output <run_id> task-id -o ./artifacts` downloads that task's stored files through Tracker. Pass a complete relative file path to download one file. Paths remain relative to the run inside the destination, which must be a new directory.

Python callers can inspect a page with `await client.artifacts.list(run_id, prefix="task-id")`, request an individual temporary URL with `await client.artifacts.download_url(run_id, "task-id/result.json")`, or download a path with `await client.artifacts.download(run_id, "./artifacts", path="task-id")`. See the [artifact SDK reference](/reference/sdk/artifacts) for limits and pagination.

Hosted runs use the deployment's storage permissions. Legacy runs started with caller-supplied AWS credentials still require that configuration. Tracker checks access to the run before listing or signing an artifact.
