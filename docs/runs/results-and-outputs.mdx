Valkyrie keeps two things apart: the evaluated results, and the files the agent produced along the way.

<CodeGroup>

```bash CLI
valkyrie run results <run-id> --path ./results.json
```

```python Python SDK
results = await client.runs.results(run_id)
```

</CodeGroup>

Full syntax is in the [`run results`](/reference/cli/run#results), [`run outputs`](/reference/cli/run#outputs), and [`run output`](/reference/cli/run#output) reference, and in [`client.runs.results`](/reference/sdk/runs#results) for Python.

## Download results

The results file holds the scores and the per-task evaluation. Without `--path`, the CLI writes it to `./results-<run-id>.json`.

Pass a task subset to recompute `final_score` over only those tasks. The stored full result stays as it was:

```bash
valkyrie run results <run-id> --task-ids task_1,task_2
```

<Warning>
  Combining `--s3` with a task subset overwrites the run's S3 result file with that subset view. Run the command again without filters to put the full result back.
</Warning>

## Download outputs

Outputs are the files the agent itself wrote. Fetch all of them, or only the tasks you care about:

```bash
valkyrie run outputs <run-id> --output-dir ./outputs
valkyrie run outputs <run-id> --task-ids astropy__astropy-7606,django__django-10880
```

To pull one file or directory instead of the whole run, name a path inside the run's benchmark prefix:

```bash
valkyrie run output <run-id> <subpath> --output-dir ./output-dir
```

The output directory defaults to `./<run-id>`.


## Download outputs from Python

Use `await client.runs.download_outputs(run_id, "./outputs", task_ids=["task-id"])` to download and unpack run outputs, including nested task tarballs. Omit `task_ids` for the entire run. Choose a new output directory; existing directories are refused. Downloads and extraction enforce [configurable size and entry limits](/reference/sdk/runs#download-outputs) and reject links or unsafe archive paths.

## Download a specific artifact path

Use `valkyrie run artifacts <run_id> --format json` to list one page of available paths. Continue with the returned `next_cursor` using `--cursor`.

`valkyrie run output <run_id> task-id -o ./artifacts` downloads that task's stored files through Tracker. Pass a complete relative file path to download one file. Paths remain relative to the run inside the destination, which must be a new directory.

Python callers can inspect a page with `await client.artifacts.list(run_id, prefix="task-id")`, request an individual temporary URL with `await client.artifacts.download_url(run_id, "task-id/result.json")`, or download a path with `await client.artifacts.download(run_id, "./artifacts", path="task-id")`. See the [artifact SDK reference](/reference/sdk/artifacts) for limits and pagination.

Hosted runs use the deployment's storage permissions. Legacy runs started with caller-supplied AWS credentials still require that configuration. Tracker checks access to the run before listing or signing an artifact.

## Compare two runs

```bash
valk run compare <baseline-id> <candidate-id>
```

Compare runs from the same benchmark and dataset. The terminal summary counts improvements, regressions, unchanged tasks, and tasks that cannot be compared. Regressions appear first, with the largest score changes first within each group.

The default metric is the numeric `score` field, with higher values considered better. For another metric, use a dotted path and change the direction when needed:

```bash
valk run compare <baseline-id> <candidate-id> --metric metrics.cost --lower-is-better
valk run compare <baseline-id> <candidate-id> --format json
```

Task coverage includes persisted tasks in every state, explicitly configured task IDs, and IDs present in result or error records. Tasks with no evaluation are shown as missing, including pending and stopped tasks. Matched means use only task IDs with finite numeric metrics in both runs; booleans are not numeric scores. Errors, absent results, and missing metrics are shown separately, never counted as zero. These means are not the benchmark's aggregate score. Benchmark versions are not verified, and unfinished runs produce partial snapshots; confirm that the runs used comparable conditions. The comparison reads results without saving or overwriting them.

Task lists and results are read separately, so active runs can change during comparison. Text output limits task details by default; JSON includes all collected task IDs. See [`run compare`](/reference/cli/run#compare) for display options.
