---
title: "Manage a run"
description: "Change a run's concurrency, stop it, shed load, and rerun stopped or failed tasks."
---

Change a run while it goes, stop it, and rerun the tasks that didn't finish. Every command
is in the [`valkyrie run` reference](/reference/cli/run). To do the same from Python, see
[Manage runs with Python](/sdk/runs).

In the commands on this page, replace *`RUN_ID`* with the run's ID, which
`valkyrie run start` prints.

## Change concurrency

```bash
valkyrie run update RUN_ID --concurrency 20
```

Raising the limit starts more tasks. Lowering it lets running tasks finish and holds back
new ones until the run is under the limit. Only a run in progress can be updated.

## Stop a run

```bash
valkyrie run stop RUN_ID
```

The Valkyrie CLI asks you to confirm. Tasks that haven't started, and tasks being set up or graded,
stop. Agents that are already running finish their task. The run shows `STOPPING` until
they do, then `STOPPED`.

To stop only some tasks and let the rest of the run go on, name them:

```bash
valkyrie run stop RUN_ID --task-ids task-a,task-b
```

`--force` also stops running agents and deletes the sandboxes:

```bash
valkyrie run stop RUN_ID --force
```

<Warning>

A forced stop deletes the run's sandboxes, or the named tasks' sandboxes, with whatever
they hold. You can't undo it.

</Warning>

## Shed load when a model hits rate limits

Lowering concurrency waits for running tasks to finish. `run shed` lowers it and stops the
most recently started tasks at once, which have done the least work, until the run is at
the new limit:

```bash
valkyrie run shed RUN_ID --concurrency 10
```

The CLI lists the tasks to stop and asks you to confirm; `--dry-run` only lists
them. The new limit must be lower than the current one. Tasks being graded count toward
the limit but are never stopped. After the rate limits clear, rerun the stopped tasks with
`valkyrie run retry`. They start over.

## Resume or retry

```bash
# Rerun the run's stopped tasks
valkyrie run resume RUN_ID

# Rerun the run's stopped and failed tasks
valkyrie run retry RUN_ID
```

- On a finished or stopped run, `resume` reruns tasks in `STOPPED`, and `retry` reruns tasks
  in `STOPPED` or `ERROR`.
- With `--task-ids` or `--task-ids-file` on a finished or stopped run, `retry` reruns
  exactly those tasks, whatever their status, and `resume` reruns them along with the
  stopped tasks. A dataset task the run never had is added to it.
- On a run in progress, `retry` reruns failed and stopped tasks, and `resume` only applies a
  new `--concurrency`.
- A run that is `STOPPING` can't be resumed or retried until it stops.

These options change what the rerun uses:

| Option | Effect |
| --- | --- |
| `--update-agent` | Uses the agent's current files in your library, so a code fix you pushed takes effect. The run keeps the contract it started with, so changes to `run_cmd`, `install_cmd`, or parameters don't. Not allowed while the run is in progress. |
| `--from-scratch` | Grades each task from the beginning, discarding saved grading progress. |
| `--benchmark-url` | Sends the rerun to a new benchmark service URL, for example after a tunnel restarts. |
| `-s ENV_VAR SECRET` | Adds or replaces a secret mapping, for example after you rotate a key. |
| `-H NAME VALUE` | Sends a header to the benchmark service. |
| `--concurrency` | Sets a new concurrency. |
| `--connect` | Streams progress after the rerun starts. |

A rerun that restarts the agent gives the task a fresh [wall limit](/runs/time-limits#wall-limit).
