## Hosted mode

Vals operates the Tracker and execution infrastructure. Your Vals login, or an access key in CI, identifies the organization for every request.

Sign in:

```bash
valkyrie login
```

The CLI uses the bench Tracker, `https://benchmark-tracker.vals.ai`, by default. To use the prod Tracker, sign in with `VALKYRIE_URL=https://benchmark-tracker-prod.vals.ai valkyrie login`; later commands use it until you sign in elsewhere. Execution uses server IAM, your organization's own storage bucket, and server-configured logs. Before starting a run, [configure a sandbox provider](/get-started/sandbox-providers) with a secret the deployment can read. Contact [contact@vals.ai](mailto:contact@vals.ai) if the organization is not enabled for hosted execution.

Agent uploads, downloads, and run analysis use the authenticated Tracker API.

## Self-hosted mode

Run your own Tracker and execution infrastructure with the [required server permissions](/self-hosting/aws-permissions). Configure its AWS resources and allowed organizations in the deployment. Map your sandbox provider to a secret with `valkyrie provider set` and grant the server permission to read it. Locally running server processes use the AWS SDK default credential chain.

Point the CLI at your Tracker:

```bash
export VALKYRIE_URL=https://your-tracker.example.com
```

A Tracker with `AUTH_REQUIRED=false` assigns requests to its default organization and needs no credentials or login, so keep the export in your shell profile. Authenticated deployments use Descope: sign in with `valkyrie login` when the deployment sets `DESCOPE_CLI_CLIENT_ID`, or set `VALKYRIE_API_KEY` to an access key. See [Choose a Tracker](/get-started/configuration#choose-a-tracker).

Read the [infrastructure guide](/self-hosting/infrastructure) before deploying the included AWS CDK application.
