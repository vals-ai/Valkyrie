The CLI stores configuration in `~/.config/valkyrie/valkyrie.yaml`. Every `config` command is in the [`valkyrie config` reference](/reference/cli/config).

## Initialize configuration

```bash
valkyrie config init
```

Initialization selects a [hosting mode](/get-started/hosting) and collects its required AWS and tracker credentials.

The SDK and CLI use the same nested AWS configuration:

```yaml
aws:
  AWS_DEFAULT_REGION: us-east-1
  S3_BUCKET: benchmark-artifacts
  LOG_GROUP: benchmarks
  LOG_RETENTION_POLICY: 365
  credentials:
    AWS_ACCESS_KEY_ID: <access-key-id>
    AWS_SECRET_ACCESS_KEY: <secret-access-key>
sandbox_providers:
  daytona: DaytonaSecrets
```

Omit `credentials` for managed execution with local AWS operations using the AWS SDK credential chain. Omit `aws` when the client needs no AWS resources.

Existing flat files must be migrated before use: move Region, bucket, and logging fields under `aws`; move access keys and any session token under `aws.credentials`. Remove those fields from the top level. `valkyrie config init` performs these moves. If your file already has access-key fields directly under `aws`, move them into `aws.credentials`. Keep API keys, sandbox providers, and benchmark settings at the top level.

Replace a legacy `DAYTONA_SECRET_NAME` entry with `sandbox_providers.daytona`.

## Set or remove a value

```bash
valkyrie config set <KEY> <VALUE>
```

```bash
valkyrie config remove <KEY>
```

Use `config set api_key` only for the Vals API key used by hosted tracker authentication. Benchmark-service credentials use the separate [authentication commands](/benchmarks/authentication).

## Configure sandbox providers

Map a provider name to an AWS Secrets Manager secret:

```bash
valkyrie config provider set daytona DaytonaSecrets
```

The first configured provider becomes the default. Change it explicitly with:

```bash
valkyrie config provider default daytona
```

List or remove provider mappings with:

```bash
valkyrie config provider list
valkyrie config provider remove <name>
```

Select another configured provider for one run with `valkyrie run start --provider <name>`. See [Configure sandbox providers](/get-started/sandbox-providers) for the Daytona secret shape.

## Environment variables

The CLI reads these variables at startup, before any configuration file is loaded.

| Variable | Effect |
| --- | --- |
| `VALKYRIE_ENV` | Legacy override for the hosted environment saved by `config init`. Accepts `bench`, `dev`, `prod` (a compatibility alias for `bench`), and `external` (the production environment). Any other value fails immediately. |
| `TRACKER_SERVICE_URL` | Overrides the tracker endpoint for every environment. |
| `VALKYRIE_CONFIG_PATH` | Overrides the configuration file path. |
| `VALKYRIE_API_KEY` | Supplies the Vals API key during `config init` in hosted mode instead of prompting for it. |
| `VALKYRIE_CLI_LOGS` | Set to `true` to print library log output. Logs are suppressed otherwise. |

Hosted setup saves the selected environment in the configuration file, so leave `VALKYRIE_ENV` unset for normal use. With `VALKYRIE_ENV=dev` the CLI uses `https://benchmark-tracker-dev.vals.ai` and `~/.config/valkyrie/dev.yaml`, so a development profile never overwrites your hosted configuration.
