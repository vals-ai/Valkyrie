The CLI stores configuration in `~/.config/valkyrie/valkyrie.yaml`. Every `config` command is in the [`valkyrie config` reference](/reference/cli/config).

## Initialize configuration

```bash
valkyrie config init
```

Hosted setup stores the selected environment and your Vals API key. The server resolves execution resources and sandbox-provider access. API-key entry is hidden at the prompt.

For local commands that access S3 directly, configure resource locations and authenticate the local AWS SDK through its default credential chain:

```yaml
aws:
  AWS_DEFAULT_REGION: us-east-1
  S3_BUCKET: benchmark-artifacts
  LOG_GROUP: benchmarks
  LOG_RETENTION_POLICY: 365
```

Omit `aws` when the client needs no direct AWS operations. A local AWS SSO profile can be selected with `AWS_PROFILE`.

## Validate an existing configuration

Configuration accepts the fields in the [SDK configuration reference](/reference/sdk/models/config#valkyrie-config). Validation names unsupported keys without printing their values. Edit the reported file to match the current schema, or rerun hosted setup to write a supported configuration while keeping benchmark endpoints and authentication.

## Set or remove a value

```bash
valkyrie config set <KEY> <VALUE>
```

```bash
valkyrie config remove <KEY>
```

Use `config set api_key` only for the Vals API key used by hosted tracker authentication. Benchmark-service credentials use the separate [authentication commands](/benchmarks/authentication).

## Sandbox providers

The server supplies the default sandbox provider and its Secrets Manager entry. Select a supported provider for one run with `valkyrie run start --provider <name>`. See [sandbox providers](/get-started/sandbox-providers) for deployment configuration.

## Environment variables

The CLI reads these variables at startup, before any configuration file is loaded.

| Variable | Effect |
| --- | --- |
| `VALKYRIE_ENV` | Legacy override for the hosted environment saved by `config init`. Accepts `bench`, `dev`, `prod` (a compatibility alias for `bench`), and `external` (the production environment). Any other value fails immediately. |
| `TRACKER_SERVICE_URL` | Overrides the tracker endpoint for every environment. |
| `VALKYRIE_CONFIG_PATH` | Overrides the configuration file path. |
| `VALKYRIE_API_KEY` | Supplies the Vals API key during `config init` in hosted mode instead of prompting for it. |
| `VALKYRIE_CLI_LOGS` | Set to `true` to print library log output. Logs are suppressed otherwise. |

Hosted setup saves the selected environment in the configuration file, so leave `VALKYRIE_ENV` unset for normal use. With `VALKYRIE_ENV=dev` the CLI uses `https://benchmark-tracker-dev.vals.ai` and `~/.config/valkyrie/dev.yaml`, so a development profile never overwrites your hosted configuration.

## Configure benchmark services

Custom benchmark endpoints and credentials use `config service` and `config auth`. See [Custom benchmark services](/benchmarks/custom-services) and [Benchmark authentication](/benchmarks/authentication).
